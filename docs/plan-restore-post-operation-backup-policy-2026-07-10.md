# 恢复与导入合并后的备份写出策略计划

日期：2026-07-10

## 背景

本次审计覆盖两个入口：

- 主 UI 的恢复：云端1、云端2、本地来源下的导入合并、补丁恢复、覆盖恢复。
- HTML 历史页面：补丁撤销、覆盖撤销、补丁恢复、覆盖恢复、导入合并。

当前问题不是恢复前读取来源数据，而是恢复完成后的“再次写出备份产物”没有按左侧“设置与初始化”里的 `Versioned / Overwrite` 策略走。

当前左侧策略保存键为 `chrome.storage.local.overwriteMode`，取值为：

- `versioned`：多版本
- `overwrite`：覆盖

普通备份上传会读取这个键；恢复/导入合并后的特殊写出链路目前没有正确使用它。

## 当前现状

| 操作 | 当前是否会写出备份产物 | 当前写出策略 | 当前快照 | 当前变化数据 |
|---|---:|---|---|---|
| 主 UI 导入合并 | 会 | 强制 `versioned` | 按恢复记录写出 | 可能写出，但落点强制多版本 |
| 主 UI 补丁恢复 | 会 | 跟随来源记录的 `overwriteMode` | 按恢复记录写出 | 按恢复记录/精简策略处理 |
| 主 UI 覆盖恢复 | 会 | 跟随来源记录的 `overwriteMode` | 按恢复记录写出 | 内部历史变化数据会被清掉，容易表现为只有快照 |
| HTML 导入合并 | 会 | 强制 `versioned` | 按恢复记录写出 | 可能写出，但落点强制多版本 |
| HTML 补丁恢复 | 会 | 跟随源记录 `record.overwriteMode` | 按恢复记录写出 | 按恢复记录/精简策略处理 |
| HTML 覆盖恢复 | 会 | 跟随源记录 `record.overwriteMode` | 按恢复记录写出 | 内部历史变化数据会被清掉 |
| HTML 补丁撤销 | 不会普通写出 | 不适用 | 不写出 | 不写出 |
| HTML 覆盖撤销 | 不会普通写出 | 不适用 | 不写出 | 不写出 |

当前结果：

- 用户左侧选择“覆盖”时，导入合并仍可能新增多版本记录。
- 用户左侧选择“覆盖”时，从版本化来源执行覆盖恢复，也会新增多版本记录。
- 覆盖恢复后的历史记录可能只有快照，没有变化数据。

## 目标规则

### 总原则

| 项目 | 目标 |
|---|---|
| 恢复前读取来源 | 保留。云端来源需要拉取目标文件，本地来源需要读取本地文件。 |
| 恢复后写出备份 | 保留。恢复、补丁恢复、覆盖恢复、导入合并完成后继续写出当前状态。 |
| 写出策略 | 统一按当前左侧 `overwriteMode` 走，不再按来源记录策略走。 |
| 导入合并 | 不再强制 `versioned`，按当前左侧策略写出。 |
| 撤销 | 暂时保持不做普通备份写出，只写事务、临时安全快照和必要边界。 |
| 状态与角标 | 按实际书签状态刷新；不要把来源策略当成目标策略。 |

### 下载与上传语义

| 阶段 | 云端1/云端2 | 本地 |
|---|---|---|
| 恢复前 | 读取/下载所选目标快照或变化文件 | 读取用户选择的本地文件或文件夹 |
| 恢复后 | 上传当前浏览器状态生成的新备份产物 | 通过浏览器下载保存新的本地备份产物 |

恢复后不应再发生额外的“从云端下载”。恢复后只有写出方向：

`当前浏览器书签状态 -> 云端1 / 云端2 / 本地`

## 目标现状

| 操作 | 目标是否写出备份产物 | 目标写出策略 | 快照数据 | 变化数据 |

| 主 UI 覆盖恢复 | 会 | 当前 `overwriteMode` | 按快照开关写出 | 按变化开关写出恢复前 -> 恢复后的变化，并标记覆盖边界 |
| HTML 导入合并 | 会 | 当前 `overwriteMode` | 按快照开关写出 | 按变化开关写出导入前 -> 导入后的实际变化 |

| HTML 覆盖恢复 | 会 | 当前 `overwriteMode` | 按快照开关写出 | 按变化开关写出恢复前 -> 恢复后的变化，并标记覆盖边界 |

## 快照与变化数据矩阵

恢复/导入合并后的写出应继续遵循现有开关，而不是强制二选一。

| 快照数据开关 | 当前变化开关 | 恢复后写出结果 |
|---:|---:|---|
| 开 | 开 | 同时写出快照和变化数据 |
| 开 | 关 | 只写出快照 |
| 关 | 开 | 只写出变化数据 |
| 关 | 关 | 不写出外部快照/变化产物，只保留内部操作记录、事务和必要基线 |

说明：

- 快照数据格式继续按快照设置选择 HTML 或 JSON。
- 变化数据继续按当前变化设置选择 HTML/JSON、视图模式，以及 Changes JSON 的 Original/Canvas 格式。
- 内部备份历史的 `saveSnapshotData` / `saveChangeData` 仍由备份历史精简设置控制。
- 覆盖恢复不应无条件清空内部变化数据。若 `saveChangeData` 开启且恢复前/恢复后树可用，应保留操作级变化数据；同时标记这是覆盖恢复边界，避免后续补丁链跨过 ID 重建边界。

## 写出落点规则

| 当前 `overwriteMode` | 快照落点 | 变化数据落点 | 备份历史 log |
|---|---|---|---|
| `overwrite` | `Overwrite/` 固定文件 | `Overwrite/` 当前变化固定文件 | 不生成版本化 log，必要时更新覆盖相关索引/边界 |
| `versioned` | `Versioned/<snapshotKey>/` | `Versioned/<snapshotKey>/` | 生成或更新 `backup-history-log.md` |

来源只作为溯源信息保留，例如：

- 恢复自哪个序号。
- 恢复自哪个时间。
- 恢复自版本化还是覆盖来源。
- 恢复自云端1、云端2还是本地。

来源不再决定本次恢复后的写出落点。

## 实现计划

1. 增加统一的恢复后写出策略解析。
   - 在后台集中读取当前 `chrome.storage.local.overwriteMode`。
   - 归一化为 `versioned` 或 `overwrite`。
   - 恢复/导入合并后的写出统一使用这个值。

2. 调整 `handleTriggerRestoreBackupMessage` 的模式选择。
   - 当前逻辑：`merge -> versioned`，非 merge -> `sourceOverwriteMode`。
   - 目标逻辑：恢复后写出模式 -> 当前 `overwriteMode`。
   - `sourceOverwriteMode` 继续保存在 `restoreInfo` 里，只做来源说明。

3. 调整主 UI 恢复 payload。
   - 保留 `restoreRecordMeta.sourceOverwriteMode` 用于展示来源。
   - 不再让它控制恢复后写出落点。

4. 调整 HTML 历史页恢复 payload。
   - `restoreToHistoryRecord` 仍可记录源 `record.overwriteMode`。
   - 实际写出落点改为当前 `overwriteMode`。
   - `merge` 不再强制 `versioned`。

5. 保持撤销链路不触发普通备份写出。
   - 补丁撤销、覆盖撤销继续写事务和临时安全快照。
   - 覆盖撤销继续写比较边界。
   - 不上传云端1/云端2，不下载本地备份文件。

6. 调整覆盖恢复的变化数据保留策略。
   - 覆盖恢复仍标记为边界事件。
   - 若变化数据保留开关开启，且恢复前/恢复后树都可用，应保留变化数据或至少保留操作级变化摘要。
   - 不再因为 `normalizedStrategy === 'overwrite'` 就无条件把 `hasChangeData` 清空。

7. 确认状态、角标和历史展示。
   - 恢复/导入合并后按实际写出结果刷新状态。
   - 角标按当前书签基线和变化检测结果刷新。
   - 历史记录显示“导入合并自 / 补丁恢复至 / 覆盖恢复至”，同时显示当前写出策略。

| 左侧策略为版本化，主 UI 从覆盖来源覆盖恢复 | 恢复后新增版本化记录 |

| 左侧策略为覆盖，HTML 补丁/覆盖恢复 | 恢复后写到覆盖落点 |
| 左侧策略为版本化，HTML 补丁/覆盖恢复 | 恢复后写到版本化落点 |

## 风险与注意点

- 覆盖恢复会造成大量 ID 重建，变化数据可能很大；需要保留边界标记，避免后续补丁恢复跨边界误用旧 ID。
- 如果快照关闭但变化开启，变化归档必须有恢复前/恢复后树作为输入；缺失时应给出明确告警，而不是静默成功。
- 本地写出仍表现为浏览器下载，需要避免误解为“恢复前读取本地文件”。
- GitHub 覆盖落点虽然是覆盖文件，但旧版本仍可从仓库提交历史查看。
- 迁移时要保留旧记录兼容：旧记录的 `sourceOverwriteMode` 和 `overwriteMode` 不能被重新解释成当前策略。

## 不在本次范围

- 不改变恢复策略选择本身：导入合并、补丁恢复、覆盖恢复仍由恢复弹窗决定。
- 不改变撤销策略选择本身：补丁撤销、覆盖撤销仍由撤销弹窗决定。
- 不改变云端1、云端2、本地的配置开关。
- 不改变恢复前的数据读取方式。
