# Bookmark Backup 3.0 妥协与限制说明

本文档用于收纳不适合放在根目录 `README.md` 中展开的浏览器限制、功能妥协和兼容性说明。

## 限制一：语言切换 UI 与新增语言

当前语言切换只支持简体中文（`zh_CN`）与英文（`en`）。主界面的切换控件也是在这两种语言之间直接切换，并会据此更新页面内容。

现有文案并未采用可扩展的标准 i18n 资源体系；大量中英文文案以对象和索引的形式硬编码在界面脚本中。例如，主弹窗的 `applyLocalizedContent` 中集中维护了大量 `{ zh_CN, en }` 文案对。

新增一种语言时，需要逐一补齐现有文案、调用位置及其他页面的对应内容，遗漏风险较高，调试成本也较大。

即使通过 Python 等脚本整理和提取文案，文本收集本身相对容易；真正困难的是 UI 适配：不同语言的字数、换行方式和文字方向不同，需要逐个检查按钮、表单、提示语和弹窗的布局。

因此，新增繁体中文、法语、俄语、西班牙语、阿拉伯语、日语或韩语前，应在以下两条路径中选择：

- **重构语言系统**：迁移到统一的 i18n 资源与键值体系，再以语言选择 UI 驱动各页面文案。这是更适合长期维护的方案，但改动范围较大。
- **在现有结构上逐项补充**：直接为现有中英文文案对象添加目标语言，并逐页进行界面微调。这一方案适合小范围、短期补充，但维护成本会随语言数量快速上升。

阿拉伯语还需要额外验证 RTL（从右至左）排版；其他语言也应在真实内容长度下完成界面回归测试。

## 限制二：防干扰：只在本地备份时隐藏下载栏

Edge 已改为自己的下载栏，这一策略在 Edge 上已经不适用。

- **Edge 下载 UI 已变化**：Edge 从底部的 **Download Shelf（下载栏）** 切换到了工具栏的 **Download Bubble / Flyout（下载浮窗）**。
- **Chrome 新接口**：Chrome 105+ 支持 `chrome.downloads.setUiOptions({ enabled: false })` 和 `downloads.ui` 权限；旧的 `setShelfEnabled` / `downloads.shelf` 自 Chrome 117 起废弃，已不再作为主实现。
- **Edge 自有下载系统不响应**：Edge 的 **msDownloadsHub**（自有下载管理系统）不再响应这些 API。
- **Chrome 仍保持兼容**：Chrome 虽然也用了 Download Bubble，但仍保持了 API 兼容性；Edge 没有。

因此，“防干扰：备份时隐藏下载栏”只能作为 Chrome 兼容能力理解，且只应在本地备份产生下载时使用；在 Edge 上不应承诺可以隐藏下载浮窗。
